- **T-068 [Security] OTP-created accounts keep the default PIN `0000` — takeover through `POST /api/auth/login`.** **Status 2026-10-31 — option (a) implemented and pushed to `origin/main` (2026-10-31, `7020529a`; deployment not verified):** `login()` rejects PIN `0000` with the same 401 "PIN incorrect." as a wrong PIN (`DEFAULT_OTP_PIN` in `auth.service.js`); 4 tests in `legacy-auth-otp.test.ts`; ADR-0016. A user who deliberately chose `0000` as a personal PIN cannot PIN-login either. Original finding: `verifyOtp` auto-registers new accounts with PIN `0000` (`auth.service.js`, `register(cleaned, "0000", …)`); `login()` accepts it, and the endpoint (no UI caller, but reachable and unthrottled — T-005) hands out a JWT. **[Ran]** pinned by `legacy-auth-otp.test.ts` ("écart connu"): after an OTP signup, `login(phone, "0000")` returns a token. Every OTP-created account that never changed its PIN is exposed, and OTP is the only login path. **Ask first (PIN behaviour).** Options: (a) `login()` refuses PIN-login while an account is still on the default PIN — keeps Settings → PIN change working (it checks the old PIN directly); (b) OTP accounts get a random unusable PIN hash — breaks the old-PIN prompt of the PIN screen; (c) disable `/api/auth/login` and `/api/auth/register`, which the app never calls. Effort S · regression risk L–M. — *Done when:* PIN-login with `0000` fails for OTP-created accounts, the pinned test is flipped, and the PIN-change screen is checked.
