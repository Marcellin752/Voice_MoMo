- **T-041 [Debt] Ledger constraints and currency (extends T-013).** No `CHECK` on amount or balance; check-then-update without a DB transaction and with a silent in-memory fallback on error (`transaction.service.js:101-131`); currency `FCFA` in `db.js:41` vs `XOF` in `schema.sql:16`, and none on `transactions`. — *Done when:* constraints and a single currency constant exist, or the ledger is removed per T-013.

- **T-046 [Bug] Transaction boundaries and concurrency in auth tables.** No `BEGIN`/`COMMIT`/`FOR UPDATE` anywhere. - **T-049 [Debt][Security] Data lifecycle: retention, deletion, deactivation.** No `DELETE`/purge exists, so `otps` and `sessions` grow without bound; there is no user deletion, erasure or anonymisation path; `is_active = false` only blocks login — the JWT middleware never checks the database (`legacy/middleware/auth.js`), so a deactivated user keeps API access for up to 7 days; delete rules are inconsistent (sessions/notifications/`mmi_executions` CASCADE vs ledger parties SET NULL, which strips a financial row of its owner). — *Done when:* retention jobs, a documented deletion/anonymisation procedure, and middleware that enforces active and non-revoked.
